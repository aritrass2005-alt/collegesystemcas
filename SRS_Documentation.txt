Project Name: College Attendance System (CAS)

1. INTRODUCTION
--------------------------------------------------------------------------------
1.1 Purpose
The purpose of this document is to outline the software requirements for the College Attendance System (CAS). This system digitizes the traditional attendance management process, providing an automated, transparent, and multi-tiered platform for educational institutions to monitor student attendance, leave requests, and defaulters.

1.2 Scope
CAS is a web-based application built using Java (Servlets/JSP) and MySQL. It offers distinct modules for Admins, Coordinators, Teachers/Faculty, and Students. The system handles daily attendance logging, dynamic percentage calculation, leave application processing with document proof, profile management, and defaulter tracking across various departments, years, and sections.

2. OVERALL DESCRIPTION
--------------------------------------------------------------------------------
2.1 Product Perspective
CAS serves as an independent, centralized database-driven application replacing manual paper-based attendance registers. It operates via standard web browsers.

2.2 User Roles & Access Levels
1. Administrator: Global oversight. Manages system configurations, master data (users, subjects), and assigns Coordinator roles.
2. Coordinator: Administrative oversight for specific assigned sections/years. Monitors overall attendance, approves/rejects leaves, and reviews defaulters.
3. Teacher/Faculty: Conducts classes. Responsible for marking daily attendance for their assigned subjects and managing their profile.
4. Student: End-user. Tracks their own attendance progress, identifies their defaulter status, manages their profile, and applies for leaves.

3. SYSTEM FEATURES
--------------------------------------------------------------------------------
3.1 Administrator Module
- Master Data Management: Create, update, and delete Teacher and Student records.
- Subject & Class Assignment: Bind subjects to specific departments, years, and teachers.
- Coordinator Management: Assign and revoke Coordinator privileges to existing Teachers for specific sections/classes.
- Dashboard Analytics: View overall institution metrics, total students, and total faculty.

3.2 Coordinator Module
- Context Switching: Ability to switch between multiple assigned class contexts (e.g., Year 1 Section A, Year 2 Section B).
- Role Separation: Distinct workspace separate from their teaching duties, accessed via a top-header switch button.
- Defaulter List: View students dropping below the 75% attendance threshold with dynamic progress bars.
- Leave Management: Review, approve, or reject student leave applications, including viewing uploaded proof documents (e.g., medical certificates).

3.3 Teacher/Faculty Module
- Attendance Logging: Mark daily attendance (Present/Absent/Leave) for students in their assigned subjects.
- Attendance History: Review and modify past attendance logs.
- Profile Management: Update personal details, secure password changes, and upload profile photos.

3.4 Student Module
- Dashboard Analytics: View overall attendance percentage visualized via a dynamic progress ring.
- Subject & Monthly Breakdown: Review attendance statistics broken down by individual subjects and months.
- Calendar View: An interactive calendar modal visually highlighting Present, Absent, and Leave days.
- Section Defaulters: View peers in the same section who are below the attendance threshold.
- Leave Application: Submit leave requests including start date, end date, reason, and PDF/image document proofs.
- Profile Management: Update contact details and profile avatars.

4. EXTERNAL INTERFACE REQUIREMENTS
--------------------------------------------------------------------------------
4.1 User Interfaces
- Responsive Design: Built with Bootstrap 5.3 ensuring compatibility on desktop and mobile devices.
- Aesthetics: Utilizes modern UI elements including glassmorphism cards, dynamic gradients, UI-Avatars, and FullCalendar for schedule rendering.
- File Uploads: Supports `multipart/form-data` for secure profile picture and leave proof document handling.

4.2 Hardware & Software Interfaces
- Frontend: HTML5, CSS3, JavaScript, Bootstrap 5.
- Backend: Java 11+, Servlet API, JSP.
- Database: MySQL 8.0+.
- Server: Apache Tomcat 9+.
- Build System: Maven/PowerShell build scripts.

5. NON-FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------------------------
5.1 Security
- Authentication: Session-based authentication ensuring rigid role-based access control (RBAC). 
- Passwords: Encrypted storage using BCrypt.
- Data Protection: File uploads are stored securely on the server with restricted execution permissions.
- Authorization: Coordinator and Teacher boundaries strictly enforced on the backend via session checks.

5.2 Performance & Reliability
- Real-time Computation: Attendance percentages and defaulter statuses are computed dynamically via SQL queries (e.g., `AttendanceDAO`).
- File Management: Efficient I/O operations for viewing proof documents without downloading them locally.
- Uptime: Dependent on Apache Tomcat hosting parameters, designed for 99.9% local availability.
