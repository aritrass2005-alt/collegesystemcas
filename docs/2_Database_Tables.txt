TABLE 4: attendance
================================================================================
Purpose: Stores daily student attendance records per subject.

+----------------+--------------------------------------+------+-----+-------------------+----------------+
| Field          | Type                                 | Null | Key | Default           | Extra          |
+----------------+--------------------------------------+------+-----+-------------------+----------------+
| id             | INT                                  | NO   | PRI | NULL              | AUTO_INCREMENT |
| student_id     | INT                                  | NO   | MUL | NULL              |                |
| subject_id     | INT                                  | NO   | MUL | NULL              |                |
| status         | ENUM('Present','Absent','Leave')     | NO   |     | NULL              |                |
| date_time      | DATETIME                             | YES  |     | CURRENT_TIMESTAMP |                |
| is_locked      | TINYINT(1)                           | YES  |     | 0                 |                |
| appeal_status  | VARCHAR(50)                          | YES  |     | NULL              |                |
| admin_edited   | TINYINT(1)                           | YES  |     | 0                 |                |
+----------------+--------------------------------------+------+-----+-------------------+----------------+

Relationships:
  - student_id -> student.id (FK)
  - subject_id -> subject.id (FK)

Notes:
  - A unique constraint prevents duplicate attendance records for the same
    student, subject, and date.
  - is_locked: When true, prevents further teacher edits.
  - appeal_status: Tracks attendance appeals ("Pending", "Approved", etc.).
  - admin_edited: Flags records modified by admin override.

TABLE 5: faculty_attendance
================================================================================
Purpose: Stores daily teacher/faculty attendance and leave records.

+-------------------+---------------------------+------+-----+-------------------+----------------+
| Field             | Type                      | Null | Key | Default           | Extra          |
+-------------------+---------------------------+------+-----+-------------------+----------------+
| id                | INT                       | NO   | PRI | NULL              | AUTO_INCREMENT |
| teacher_id        | INT                       | NO   | MUL | NULL              |                |
| date              | DATE                      | NO   |     | NULL              |                |
| check_in_time     | TIME                      | YES  |     | NULL              |                |
| check_out_time    | TIME                      | YES  |     | NULL              |                |
| status            | VARCHAR(20)               | YES  |     | Present           |                |
| verified_by_admin | TINYINT(1)                | YES  |     | 0                 |                |
| admin_notes       | TEXT                      | YES  |     | NULL              |                |
+-------------------+---------------------------+------+-----+-------------------+----------------+

Relationships:
  - teacher_id -> teacher.id (FK)

Notes:
  - status can be: Present, Absent, Half Day, CL, CCL, EL, Normal Leave, etc.
  - verified_by_admin: 0 = Pending verification, 1 = Admin-verified.
  - Also used for faculty leave requests (where check_in_time is NULL and
    status indicates the leave type).

TABLE 6: leave_application
================================================================================
Purpose: Stores student leave applications with proof and declaration.

+----------------+--------------------------------------+------+-----+-------------------+----------------+
| Field          | Type                                 | Null | Key | Default           | Extra          |
+----------------+--------------------------------------+------+-----+-------------------+----------------+
| id             | INT                                  | NO   | PRI | NULL              | AUTO_INCREMENT |
| student_id     | INT                                  | NO   | MUL | NULL              |                |
| reason         | TEXT                                 | NO   |     | NULL              |                |
| proof_path     | VARCHAR(255)                         | YES  |     | NULL              |                |
| status         | ENUM('Pending','Approved','Rejected')| YES  |     | Pending           |                |
| applied_on     | TIMESTAMP                            | YES  |     | CURRENT_TIMESTAMP |                |
| start_date     | DATE                                 | NO   |     | NULL              |                |
| end_date       | DATE                                 | NO   |     | NULL              |                |
| declaration    | TINYINT(1)                           | YES  |     | 0                 |                |
+----------------+--------------------------------------+------+-----+-------------------+----------------+

Relationships:
  - student_id -> student.id (FK)

Notes:
  - Supports multi-day leave via start_date and end_date.
  - proof_path stores uploaded file (PDF/JPG/PNG, max 5MB).
  - declaration must be true for submission.
  - Pending applications can be canceled (deleted) by the student.
  - Approved/Rejected by Coordinator.

TABLE 7: coordinator
================================================================================
Purpose: Maps teacher accounts to coordinator roles for specific departments.

+----------------+---------------------------+------+-----+---------+----------------+
| Field          | Type                      | Null | Key | Default | Extra          |
+----------------+---------------------------+------+-----+---------+----------------+
| id             | INT                       | NO   | PRI | NULL    | AUTO_INCREMENT |
| teacher_id     | INT                       | NO   | MUL | NULL    |                |
| department     | VARCHAR(100)              | YES  |     | NULL    |                |
| section        | VARCHAR(10)               | YES  |     | NULL    |                |
| year           | INT                       | YES  |     | NULL    |                |
+----------------+---------------------------+------+-----+---------+----------------+

Relationships:
  - teacher_id -> teacher.id (FK)

Notes:
  - A teacher becomes a Coordinator when a record exists in this table.
  - The coordinator oversees students matching the department + year + section.
  - If section is NULL or empty, the coordinator oversees all sections.

ENTITY-RELATIONSHIP SUMMARY
================================================================================

  admin (standalone)
  student ──< attendance (via student_id)
  student ──< leave_application (via student_id)
  student ──< defaulter_list (via student_id)
  student ──< notification (via receiver_id)
  teacher ──< faculty_attendance (via teacher_id)
  teacher ──< coordinator (via teacher_id)
  teacher ──< subject (via teacher_id, alt_teacher_id)
  subject ──< attendance (via subject_id)
  subject ──< timetable (via subject_id)
  subject ──< defaulter_list (via subject_id)
  department, section, academic_year (master/config tables)
  holiday_calendar (standalone reference table)
  activity_log (standalone audit table)
